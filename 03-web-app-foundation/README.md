# 03 — Web App Foundation

## เป้าหมาย

มีสแต็กเว็บแอป "มาตรฐาน" หนึ่งชุดที่ใช้ซ้ำได้กับงานลูกค้าทุกราย แทนการเลือกสแต็กใหม่ทุกโปรเจกต์
สแต็กนี้ต้องไม่เหมือนกับสแต็ก 3D/creative ของ `creative-portfolio-2026` — งานลูกค้า SME ต้องการความเร็วในการ
ส่งมอบและความง่ายในการดูแลต่อ มากกว่าความวิจิตรทางภาพ

## สิ่งที่ต้องเรียน

- เลือกสแต็กที่ "น่าเบื่อแต่เชื่อถือได้" สำหรับงานลูกค้า: Next.js หรือ Vite + React, Tailwind CSS, deploy บน Vercel
- พื้นฐาน auth สำหรับเว็บแอปขนาดเล็ก (เช่น Clerk, Supabase Auth, หรือ session-based ง่ายๆ)
- ฟอร์ม + validation พื้นฐาน (เช่น react-hook-form + zod)
- การแยก environment (.env) และความปลอดภัยเบื้องต้น (ไม่ commit secret, ตรวจ origin ของ API)
- พื้นฐานการทำเว็บให้ responsive และผ่านมาตรฐาน a11y/SEO ขั้นต่ำ

## โปรเจกต์ที่ต้องทำ

1. สร้าง **`client-app-starter`** — repo/เทมเพลตเปล่าที่มี auth + form + deploy pipeline พร้อมใช้ เริ่มโปรเจกต์
   ลูกค้าใหม่จากที่นี่ได้ทันที ไม่ต้องตั้งค่าใหม่ทุกครั้ง
2. ทำ landing page เทมเพลต 1 แบบที่ปรับแต่งได้เร็ว (สำหรับเสนอลูกค้าที่ต้องการเว็บธุรกิจง่ายๆ)

## Checklist

- [ ] เลือกสแต็กหลักแล้วบันทึกเหตุผลใน [DECISIONS.md](../DECISIONS.md)
- [ ] `client-app-starter` รันได้ deploy ได้จริงภายใน 1 คำสั่ง/ไม่กี่คำสั่ง
- [ ] มีระบบ auth พื้นฐานพร้อมใช้ในเทมเพลต
- [ ] มี landing page เทมเพลตที่ปรับ copy/สีได้เร็ว
- [ ] เอกสารวิธีเริ่มโปรเจกต์ใหม่จากเทมเพลตนี้ (ใน README ของเทมเพลตนั้นเอง)

## งานที่สามารถรับได้ตอนนี้

- เว็บไซต์ธุรกิจขนาดเล็ก (หน้าเดียว/ไม่กี่หน้า)
- หน้าฟอร์มรับข้อมูล/นัดหมายที่ต่อเข้า Sheet หรือฐานข้อมูล
- หน้า landing page สำหรับแคมเปญ/โปรโมชัน

## สิ่งที่ยังไม่ต้องทำ

- ❌ Multi-tenant architecture — รอ [09-saas](../09-saas/)
- ❌ Design system/component library ขนาดใหญ่ — ใช้ Tailwind ตรงไปตรงมาก่อนพอ
- ❌ Micro-frontend หรือ monorepo หลายแอป — ยังไม่มีจำนวนโปรเจกต์มากพอที่จะคุ้มความซับซ้อนนี้
- ❌ เลือกสแต็กที่ต้อง maintain เยอะ (เช่น custom framework, GraphQL เต็มรูป) สำหรับงานลูกค้าขนาดเล็ก
