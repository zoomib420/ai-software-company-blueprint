# 06 — Mini ERP

## เป้าหมาย

แปลง Schedule Automator & Classroom Creator (ที่มีอยู่แล้ว: reverse-engineer ERP เดิม → sync ข้อมูลเข้า Google
Sheet → สร้าง classroom อัตโนมัติ) ให้กลายเป็น "Mini ERP" ที่เป็นเทมเพลตขายซ้ำได้ ไม่ใช่ทำใหม่จากศูนย์
(ดู [DECISIONS.md](../DECISIONS.md) ADR-0003)

**อย่าเริ่ม stage นี้แบบจริงจังก่อนมีลูกค้าจริงขอ** — ใช้ Schedule Automator ตัวเดิมขายงานไปก่อนใน
[01-first-client](../01-first-client/)

## สิ่งที่ต้องเรียน

- พื้นฐานโดเมน ERP สำหรับ SME: ตารางเวลา/การจอง, สต๊อกสินค้า/วัสดุ, เอกสารง่ายๆ (ใบเสนอราคา/ใบส่งของ)
- Pattern การ sync ข้อมูลข้ามระบบแบบไม่มี API (reverse engineering ที่ทำมาแล้วจริงกับ ERP สถาบันกวดวิชา)
- การทำ dashboard สรุปสถานะที่เจ้าของธุรกิจเข้าใจได้ในแว่บแรก (ไม่ต้องอ่านตาราง raw data)
- พื้นฐานความปลอดภัยเมื่อต้อง login เข้าระบบของลูกค้า (เก็บ credential ยังไงให้ปลอดภัย, สิทธิ์เข้าถึงขั้นต่ำ)

## โปรเจกต์ที่ต้องทำ

1. Generalize Schedule Automator: แยกส่วน "ตรรกะ sync ข้อมูล" ออกจากส่วน "เฉพาะ ERP ของสถาบันเดิม" ให้ปรับ
   ใช้กับระบบอื่นที่หน้าตาคล้ายกันได้เร็วขึ้น
2. ทำ Mini ERP demo ทั่วไป 1 ชุด: ระบบจองคิว/ตารางเวลา + สต๊อกง่ายๆ ที่ไม่ผูกกับ ERP เฉพาะเจ้าใดเจ้าหนึ่ง
   (ใช้ backend จาก [04-database-backend](../04-database-backend/))

## Checklist

- [ ] มีลูกค้าจริงอย่างน้อย 1 รายขอระบบแบบนี้ก่อนเริ่ม generalize เต็มรูป
- [ ] แยกตรรกะ sync ออกจาก business logic เฉพาะเจ้าเดิมได้ชัดเจน
- [ ] มี Mini ERP demo ที่ไม่ผูกกับลูกค้าเดิมเจ้าเดียว ใช้โชว์ลูกค้าใหม่ได้
- [ ] มี dashboard สรุปสถานะที่ไม่ใช่ raw table
- [ ] ทดสอบกับลูกค้าจริงรายใหม่ (หรือลูกค้าเดิมรายที่ 2) จนใช้งานได้ครบวงจร
- [ ] เขียนเป็น case study ใหม่หลังใช้งานจริงสำเร็จ

## สิ่งที่ยังไม่ต้องทำ

- ❌ Generalize เป็นโปรดักต์ก่อนมีลูกค้าจริง 1 รายขอ
- ❌ ระบบบัญชีแบบ double-entry เต็มรูป — เกินความจำเป็นสำหรับ SME ขนาดเล็กในช่วงนี้
- ❌ รองรับหลายคลัง/หลายสาขา (multi-warehouse) — เริ่มจากเคสเดียวให้ลื่นก่อน
- ❌ แปลงเป็น SaaS — รอ [09-saas](../09-saas/) และสัญญาณ demand ตาม ADR-0002
